# 回响 0.4 页面与流程重构提案

日期：2026-10-27。状态：用户已确认并要求采用年轻、有活力的视觉。本轮已实现主要页面与流程，构建目标为 0.4.0；实际验证范围见 [验收记录](VALIDATION.md)。以下保留方案及后续设备验收目标。

## 目标与边界

把回响作为独立的移动端产品设计，重新组织页面、导航、视觉和交互。上游用于核对功能完整性；已验证的 TeamSpeak 协议、音频、串流和加密存储继续作为底层能力，不将本次界面重构扩大成协议重写。

本轮先把登录、服务器、好友和语音流程做顺。文件传输、屏幕/摄像头共享、频道管理、身份导入导出和高级音频设置保留对应入口，不因页面简化而删除功能。不在界面重构中承诺新增尚未支持的云端加密消息解密、新建好友会话或多服务器同时语音连接。

## 当前结构与问题

- `MainActivity.App()` 以入口选择和语音连接状态切换主要页面，账号另以 `CloudAccountDialog` 覆盖其上。连接前后缺少稳定的主导航。
- 账号弹窗同时承载登录、服务器书签、好友、云会话和迁移导入；本机收藏与账号书签的常用入口分散。
- `CloudAccountController` 的生命周期跟随账号弹窗，重开会重新恢复并拉取好友。页面关闭会取消控制器的任务，不适合作为全局账号状态的所有者。
- 连接页默认展示昵称、地址、密码及多个选项；熟悉服务器的登录用户仍要面对完整表单。
- 服务器页和设置页拥有大量弹窗布尔状态。设置用五个横向分类和保存操作承载多种性质的选项，手机上的层级不直观。

## 新的信息架构

主框架采用四个固定底部入口：**服务器、好友、消息、我的**。服务器为默认首页；语音房间和会话是详情路由，不另做第五个底部入口。

| 页面 | 内容与主要操作 |
| --- | --- |
| 欢迎与登录 | 小怪兽、回响名称、主按钮“登录 TeamSpeak 账号”、次按钮“访客进入”；登录表单独立页面，OTP 按需显示。 |
| 服务器 | 最近连接、账号书签、本机收藏；使用来源标记区分。点击书签连接；添加、手动连接及粘贴邀请放在统一入口。默认不铺开完整连接表单。 |
| 好友 | 自动加载并缓存的好友列表、可读名称和本地搜索；好友详情能打开已有云会话。没有可信在线状态时不绘制在线圆点。 |
| 消息 | 好友云端会话及其历史。未启用时提供明确的“连接云消息”操作，不自动请求云聊天登录。服务器内频道聊天和私聊仍位于对应服务器。 |
| 我的 | 当前账号或访客身份、登录/切换/退出账号；发言方式、音频设备、后台运行、外观语言、隐私与身份、关于与诊断。迁移导入收进账号高级项。 |
| 语音房间 | 服务器与当前频道、频道树和成员；“频道 / 聊天”切换，明显的按住说话区；麦克风、声音、音频输出与明确的断开操作。文件和共享按所属频道或会话提供入口。 |

账号书签和本机收藏保留各自的数据来源。相同地址但昵称、身份或连接配置不同的条目不能静默合并，也不能把本机修改冒充为云端写入。

## 关键流程

### 启动与登录

1. 首次启动显示欢迎页。保存了有效本机账号时恢复到服务器首页；曾明确选择访客时可记住访客模式，并保留登录入口。
2. 登录仅由账号认证与会话保存决定成功。成功立即进入主框架；书签和好友各自后台加载，不阻塞首页，也不要求先连接云聊天。
3. 先展示本地缓存，再按刷新策略更新。加载失败保留可用的缓存，并显示数据来源及是否过期。
4. 登录用户默认使用账号用户名，连接时可手动覆盖，书签专用昵称也保留。访客首次连接填写昵称，后续记住。
5. 会话失效只影响需要账号的功能；用户仍可使用本机服务器和正在进行的独立语音连接。

### 连接与持续语音

1. 点击保存的服务器直接进入连接流程；只有缺少密码、首次访客昵称等必要信息时才补充输入。
2. 已连接同一条配置时返回房间，不重复连接；切换到另一服务器前确认将离开当前连接。
3. 连接中、成功、重连和失败都有对应状态与明确的下一步。失败可以重试或修改连接信息，不能永久停留在加载状态。
4. 离开语音房间页面或切换底部入口，通话继续。主框架底部显示精简的当前频道条，可回到房间及查看/切换静音。
5. 返回上一页不等于断开服务器。只有明确的断开操作结束连接；退出云账号也不隐式断开独立的服务器语音。
6. 按住说话在松手、手势取消、页面失去交互等情况下停止发送，避免导航重构导致持续发声。
7. 外部邀请优先显示连接确认；包含的密码、频道和权限密钥不在列表或日志中泄露。自动连接仅在完成入口选择后按已有设置执行，不抢占邀请确认。

### 好友与云消息

1. 账号恢复后自动加载好友，切换页面不会清空结果或取消全局请求；再次进入优先使用已加载的数据。
2. 名称优先使用可读备注和已验证的公开显示名称。名称查询失败保留上一份可用名称或友好占位，绝不把 Base64、JSON 或不透明账号 ID 当昵称。
3. 好友列表、公开名称读取和云聊天会话分别管理请求与错误。公开名称可能读取聊天域名上的公开资料，但不代表已建立云聊天登录。
4. 云消息保持显式启用。503 只影响云消息区域，显示重试与详情，不撤销账号、不清空服务器和好友缓存。
5. 点好友只能打开实际存在且受支持的会话；没有会话时给出明确解释。暂不支持发送的加密房间显示只读状态并禁用输入，不提供无效发送操作。
6. 加载、空列表、部分加载失败、离线缓存和认证失效使用不同文案。错误码与诊断放入“查看详情”，可复制脱敏信息。

## 视觉方向

- 延用“回响”和已选紫色独眼小怪兽。深灰背景、紫色主操作、青色发言/语音反馈，状态同时用文字或图形表达。
- 欢迎页与空状态使用角色，日常服务器和频道列表以信息为主，减少大插画和重复说明。
- 统一页标题、按钮、输入框、列表行、头像、间距和错误状态；长页面采用分组设置。列表与表单适应小屏、大字号、键盘和系统安全区域。
- 常用操作放在手机易触达位置。高风险或不常用的频道管理操作进入详情菜单，并依据权限与高级设置显示。
- 保持原生 Compose；优先复用现有依赖和图形资源，避免引入网页壳、大字体包和大量动画资源。包体增量作为验收项，与 0.3.5 的 16.34 MiB arm64 包对比。

## 状态和代码组织

| 状态所有者 | 独立管理的内容 |
| --- | --- |
| 全局入口与导航 | 首次启动、登录/访客模式、当前路由、邀请确认、页面返回栈。 |
| 账号 | 认证、会话恢复、账号变更与失效；不等待书签或云消息。 |
| 服务器目录 | 本机收藏、最近连接、账号书签、各自缓存及刷新状态。 |
| 好友 | 列表、可读名称缓存、独立加载与失败状态。 |
| 云消息 | 是否主动启用、连接、会话、历史、只读与发送状态。 |
| 语音服务 | 单一服务器连接、频道、音频设备、静音/PTT、后台、串流；不跟随页面销毁。 |

采用一个主框架和明确的路由；页面由各自 ViewModel 暴露状态，数据仓库负责缓存与刷新。全局账号和语音任务归业务层管理，不能再由是否打开某个弹窗决定生命周期。

逐步替换现有 `ConnectScreen`、`ServerScreen`、`CloudAccountScreen`、`SettingsDialog` 与主题组件；不先删除旧界面。保留现有包名、签名、加密密钥别名与存储标识，在需要时编写明确的数据迁移，不能因 UI 重构而主动清空账号、收藏、聊天记录或语音身份。

## 实施顺序与验收

1. **关键页面原型**：欢迎/登录、服务器首页、语音房间、好友/消息、我的；确定导航、连接状态条、视觉和异常状态。
2. **主框架与基础流程**：统一导航与主题，接入账号恢复、访客、服务器目录和手动连接，保持原有数据可覆盖升级。
3. **语音工作区与其余功能**：接入频道/成员、PTT、服务器聊天、文件/串流，以及好友、云消息和设置；按功能清单逐项迁移。
4. **异常和交付验证**：覆盖首次启动、旧版覆盖升级、账号过期、书签/好友失败、云消息 503、切换服务器、断网重连、返回与旋转、前后台、PTT 取消和邀请确认。完成适当的单元与界面检查，再构建安装包，最后对华为畅享 70 做实际设备验收。

完成标准：常用入口固定且可预测；账号登录、语音连接和云消息故障互不牵连；页面切换不丢通话和已加载内容；旧版功能有去处、数据可继续使用；普通用户不必理解密钥或协议错误码才能完成登录和连接。
